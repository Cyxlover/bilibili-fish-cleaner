# 大肥鱼清除计划

一个 Edge / Chromium（Manifest V3）浏览器扩展：在哔哩哔哩**普通视频页**识别疑似机器人的评论（站内俗称「大肥鱼」），并在**本地**标记或收起。默认关闭。

它只做本地显示层处理：不删除、不举报、不调用任何写接口、不上传任何数据，处理过的评论随时可以恢复。

---

## 它做什么，不做什么

**做**

- 读取当前页面**已经渲染出来**的评论（昵称、正文、UP 主标记等），按固定规则判三档：隐藏 / 疑似 / 不处理。
- 「隐藏」= 把该评论从页面移出（自动清除开启时），或在页面上给它加强标记（自动清除关闭时）；「疑似」= 只加标记，不动内容。
- 提供角标开关、侧边面板（当前视频 / 账号名单 / 保留例外），以及单条评论的手动隐藏与恢复。

**不做**

- 不删除、不举报、不修改任何线上数据。
- 不自动回复，不代替你操作账号。
- 不把评论、账号或浏览记录上传到任何服务器。
- 不翻页抓全量评论，只处理当前页面已渲染的部分。

## 安装（Edge）

**给普通用户**：到 [Releases](../../releases) 下载最新 `bilibili-fish-cleaner-v*.zip`，解压到一个不会随手删掉的目录（例如 `D:\Apps\bilibili-fish-cleaner`），然后：

1. 地址栏打开 `edge://extensions`。
2. 打开「开发人员模式」。
3. 点「加载解压缩的扩展」，选择**解压出来的目录**（即 `manifest.json` 所在的那一层）。
4. 打开任意视频页（`https://www.bilibili.com/video/...`），页面**右下角**会出现角标。

移动目录或重新解压到新位置会让浏览器重新生成扩展 ID，已保存的状态不会跟过去。

**给开发者**：也可以直接「加载解压缩的扩展」指向本仓库根目录，改完代码在扩展页点一下刷新即可。

## 使用

### 角标（页面右下角，固定定位）

- 显示本页的「一级评论」与「楼中楼」数量。
- 「自动清除：关 / 开」按钮切换整页的规则处理，默认关闭。
- 关闭状态下，被判为隐藏的评论仍带标记但不收起，方便你先观察判定是否合理；关闭的瞬间，本页仅由规则隐藏的评论会被放回，手动隐藏与账号名单不受影响。

### 清除强度（角标上的三档）

角标上有「清除强度」下拉，切换立刻生效（换档会把本页规则隐藏的评论先放回、再按新口径重扫）：

| 档位 | 行为 | 隐藏数 | 召回 | 真人被隐藏 |
| --- | --- | --- | --- | --- |
| 保守 | 只认「本条评论自身」的证据（规则 v1） | 197 | 22.7% | 4 条（0.1%） |
| 标准 | 本条证据或本页结构证据（v2b） | 382 | 44.6% | 8 条（0.3%） |
| **激进（默认）** | 标准口径，并且「疑似」也一并隐藏 | **642** | **70.4%** | 38 条（1.2%） |

数字来自 400 条独立盲标样本、按规则分层加权回 3931 条评论总体。档位存在 `chrome.storage.local` 的 `dshcc.purge.strength`。

想少误伤就调低到「保守」；想尽量清净就留在「激进」——被误隐藏的评论都能在面板里逐条「恢复这条」，恢复后进入「保留例外」，规则不会再动它。

### 侧边面板（点击工具栏图标）

- **当前视频**：本次页面加载里的隐藏记录，规则判的和手动隐藏的都在，带原因、命中线索与强度、规则版本、时间；每条都有「恢复这条」。「清空规则记录」只清空规则命中的记录，不会把已隐藏的评论放回来，也不影响账号名单与保留例外。
- **账号名单**：已屏蔽与已保留（允许）的账号；可以对单个账号「取消屏蔽」「取消保留」。
- **保留例外**：你恢复过的评论。进入这里之后，规则不会再自动隐藏它。该视图是只读列表。

面板是独立扩展页面，拿不到页面里的 DOM，记录通过消息桥向当前活动标签页取；停在非 B 站标签上时退回本地状态并显示空态。

### 单条评论的手动操作

- 鼠标移到评论上出现「隐藏」；隐藏一条一级评论等于隐藏整串，隐藏楼中楼只影响该条。
- 手动隐藏后，页面底部提示条提供「撤销」与「屏蔽作者」。
- 面板里「恢复这条」会把该评论加入「保留例外」，规则之后不再隐藏它；恢复评论**不会**解除该作者的账号屏蔽。
- 账号维度的处理（屏蔽 / 保留）只在面板「账号名单」里改变，规则命中不会把作者自动写进账号级名单。
- 「允许账号（保留账号）」的状态机与控制器已经支持（加入后该作者不会被规则自动隐藏，也可取消）；0.1.0 的面板只提供查看与「取消保留」，页面上没有「加入保留账号」的入口。

优先级从高到低：保留例外 > 手动隐藏 > 账号屏蔽 > 允许账号 > 规则判定。

## 判定规则怎么工作

引擎在 `engine/`，是纯函数：不读 DOM、不发网络请求、不读设置、不取当前时间。同一份观测 + 同一规则版本，结果恒定。

- **隐藏（hide）**：需要「身份元数据」与另一份独立来源的证据同时成立。
  - 身份元数据：昵称含明确的鱼 / 鲸词、简介含相关自述等。
  - 另一份证据：正文母题（正文自指鱼 / 鲸、括号里的身体动作描写、称呼对方为「主人」、身体部位 / 动作词、隐含人设语汇等），或（v2b 起）本页的分享结构。
  - 证据按来源计，同一来源不累加，至少两个独立来源才算数。
- **疑似（suspect）**：只有身份元数据、不足以定性；或长文本身是完整可核的技术 / 教程叙事（长评豁免）。只标记，不收起。
- **不处理（none）**：其余。

当前默认规则版本 `v2b-longform@2026.10.23`。旧版本规则已冻结（`engine/rules.js` 的 `FROZEN`），改规则必须新增版本号；`test/engine/*.test.js` 是规则回归守卫。

简介线索按需读取：不是每条评论都请求，只在需要这一项证据时经 Service Worker 取一次公开简介，并缓存。

## 准确度与已知局限

这一节是真实数字，不做美化。

- 用 400 条独立盲标样本复核（标注者不看规则判定结果）：**标准口径召回约 45.6%**，即大约一半的机器人评论抓不到；**激进口径召回 70.4%**，代价是 38 条真人评论被隐藏（加权 1.2%）。
- **标准口径的加权误隐藏点估计为 0 条**，但 400 条样本只能排除「误伤率 ≥ 2%」，无法从统计上证实「绝对零误伤」（95% 上界约 7.5 条 / 3931 条）。激进口径的误隐藏是实测的 1.2%，不是估计上界。
- 标准口径**未达到当初的验收线**（召回 45.6% vs 50%）。产品策略因此是：**默认关闭自动清除 + 只做本地隐藏 + 命中处强标记 + 一键恢复**，把误伤的代价压到最低；召回不足交给「激进」档与手动隐藏补。

其他局限：

- 只在 `bilibili.com/video/*` 生效，动态、专栏、直播不支持。
- 只处理当前页面已渲染的评论，不翻页；未登录或被限流时页面渲染得少，能处理的数量也少。
- 召回偏低（见上）；「疑似」只标记，不隐藏。
- 首次安装没有本机历史，依赖「跨视频复读 / 反复 @ 同一批人」的线索不命中，要攒够历史才生效。
- 「规则隐藏」记录只活在本次页面加载内，刷新后重新判定；「手动隐藏 / 账号名单 / 保留例外」才持久化。
- 页面一次只渲染有限条评论，是否命中取决于这一批里是否真的同时出现身份线索与独立证据，所以不同视频的命中数量差异很大。

## 隐私

- 所有判定在浏览器本地完成，无上报、无遥测。
- 唯一的网络请求是按需读取 B 站公开的用户简介（`https://api.bilibili.com/*`），请求不带登录态（`credentials: 'omit'`），只读 `card.sign` 一个字段。
- 简介缓存只落 `{sign, at}`，不落昵称、头像、等级、关注关系；有效期 7 天，最多 50 条（`chrome.storage.local`，键 `dshcc.profile.cache.v1`）。
- 状态存在 `chrome.storage.local`：`dshcc.state.v1`（账号名单、手动隐藏、保留例外），`dshcc.purge.enabled`（开关）。
- 不申请 `tabs`、`history`、`webRequest` 等权限，也不调用任何写接口。

## 开发

```bash
npm test                        # 252 条用例、46 个测试套件，全部通过
npm run check                   # 语法 / 引擎产物新鲜度 / manifest / 单测 / 规则回归，一次跑完
node tools/regression.mjs       # 规则回归 CLI，与评估报告数字对齐
node scripts/build-engine.mjs   # 改 engine/ 后重建 src/lib/engine-bundle.js
```

约束：

- 引擎层 `engine/` 保持纯函数，可在 node 里单独跑；契约与 API 见 `engine/README.md`。
- `test/engine/*.test.js` 有 26 条规则回归用例，钉住各规则版本的行为。
- 已发布规则版本不可改写，只能新增版本（旧版本保留在 `FROZEN` 中供回归对照）。
- 改了 `engine/` 之后要重建内容脚本用的打包产物，否则浏览器里跑的仍是旧引擎。
- 内容脚本按 `manifest.json` 中的顺序加载，模块之间通过全局命名空间 `DSHCC` 暴露，顺序错误会缺依赖（`test/manifest-order.test.mjs` 守卫）。
